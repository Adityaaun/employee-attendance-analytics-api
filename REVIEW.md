# REVIEW.md

| Defect # | Where | What was wrong | How it was detected | How it was fixed |
|---|---|---|---|---|
| 1 | `GET /health` | Did not perform a MongoDB ping, returning a hardcoded success status instead. | `GET /health` returned HTTP 200 even when the MongoDB connection string was broken or the database was offline. | Replaced the hardcoded return with a native `db.command("ping")` that correctly raises HTTP 503 upon failure. |
| 2 | `POST /employees` | Employee creation relied on unsafe check-then-insert validation behavior for `emp_code` uniqueness. | Test concurrency runs flagged race conditions where two identical submissions sneaked past the application-layer check. | Stripped Python-level checks and enforced a unique index at startup, gracefully catching `DuplicateKeyError` to return HTTP 409 natively. |
| 3 | `POST /attendance/punch-in` | The punch-in timestamp/date handling lacked proper overnight bounds logic and shifted dates inaccurately. | A punch-in at 02:00 for an overnight shift incorrectly registered against the current calendar day rather than the preceding workday. | Implemented `shift_end <= shift_start` logic inside `compute_attendance_date` to reliably subtract one calendar day for early-morning punches. |
| 4 | `compute_late_minutes()` | Subtracted the 10-minute grace period from the total tardiness mathematically. | Any late arrival (e.g., 15 minutes) incorrectly resulted in only 5 `late_minutes` rather than the required 15. | Restructured the helper to return the *entire* floor elapsed time from `shift_start` strictly if the 10-minute grace period is breached. |
| 5 | `compute_overtime_minutes()` | Function permitted minuscule/fractional amounts of overtime (e.g., 10 minutes) instead of enforcing the strict threshold limit. | Test cases flagged non-zero overtime on punches 15 minutes past the `shift_end` boundary. | Embedded a rigid `total_minutes >= 30` condition, returning 0 if the employee punched out sooner than the 30-minute threshold. |
| 6 | `compute_work_hours()` | Derived calculations utilized Python's native `round()` which applies `ROUND_HALF_EVEN` (Bankers Rounding). | Edge cases mathematically landing directly on `.005` were inexplicably rounded downwards dynamically. | Replaced standard rounding with deterministic `Decimal` casting utilizing explicit `ROUND_HALF_UP` quantization. |
| 7 | `PATCH /attendance/{emp_code}/{date}` | Regularization endpoints lacked required atomic optimistic-concurrency behavior, risking lost updates. | Twin background regularization requests on the identical date caused the latter request to blindly overwrite the former without conflict warnings. | Injected BSON `history` snapshot arrays, wrapping updates in `find_one_and_update` with exact size expectations to yield safe HTTP 409s. |

### Starter behavior that was reviewed and retained

The core timezone mapping logic responsible for parsing incoming date strings and forcing UTC alignments natively through IST (+05:30) offset translation mathematically looked suspicious originally, but upon verification against the strict BSON datetime rules (enforcing exact localized interpretation regardless of host time), the structural validation was definitively valid and therefore retained without modification.
